# Design

## Context

参见 proposal.md。自动入口需继续在用户配置阈值内强制执行 ACME 命令，但 force 当前同时控制状态保护；部署入口已有异常失败契约。

## Goals / Non-Goals

Goals: 保留手工强制续签行为、全云部署范围和已有异常契约，以最小改动修复四项风险。
Non-Goals: 不改鉴权、密钥管理、SSH 文件替换和权限、TLS 探测告警、存储架构。

## Decisions

- 增加 automatic 参数，将自动入口状态保护与 ACME force 分离。自动流程强制执行命令但不能绕过冷却或待人工部署状态；collector 传入同轮已处理证书集合，续签编排复用已有解析结果去重，保留原始请求域名、解析失败记录与通知。
- 本轮域名采集失败时跳过证书采集，即使有历史快照也不自动操作旧清单；独立 ECS 与绑定采集继续，汇总错误供调度下一轮重试。
- 保留 apply_deploy 抛异常契约，使用携带结构化结果的部署异常。实时校验接口异常标记为失败；实时确认已移除目标仍正常跳过。
- Nginx 规划错误报错，认证及目标字段错误形成失败结果，不再返回空结果掩盖失败；保留其他云已完成的结果。
- dry-run 返回 deploy_status=planned、说明尚未部署，不写续签部署成功状态；apply 完整成功返回 success，存在成功与失败目标返回 partial_failed，全失败返回 failed。签发状态与部署状态分别表达。
- 构建流程将新版本镜像标记为 latest，再推送两个标签。

## Risks / Trade-offs

- 自动失败保护可能要求人工恢复 → 日志明确提示仅部署入口，保留手工强制行为。
- 旧调用者可能只捕获 RuntimeError → 新部署异常继承 RuntimeError，保留既有调用方式。
- 镜像仓库推送依然可能中途失败 → 沿用 set -eu，不增加发布或外部操作。

## Migration Plan

部署代码即可生效，无配置迁移；已有 deploy_failed 状态会阻止自动重新签发，需通过仅部署成功恢复。回退代码可恢复旧行为，不更改状态文件格式。
