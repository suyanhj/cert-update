## Context

强制续签在 await 后直接进入旧 client 上下文；通知辅助函数只判断注册状态，没有检查断开；配置控件在保存后无条件更新。

## Goals / Non-Goals

复用统一客户端可用性判断，业务执行与页面寿命分离；不延长重连超时，不取消正在执行的签发或部署。

## Decisions

- 使用 NiceGUI 公共 is_deleted 与 has_socket_connection 判断客户端是否可更新，跳过已销毁或断开页面。
- 所有强制续签结果通知使用现有安全通知函数；配置保存 await 之后先检查客户端再更新控件。
- 手动采集只对有效连接触发刷新，采用无需等待返回结果的 JavaScript，避免刷新过程等待响应。
- 固定 nicegui==3.18.0，python-dotenv 同步到满足新版依赖的版本。

## Risks / Trade-offs

- 短暂断开时不发送一次性页面提示；业务结果仍写入既有状态及日志，新页面可重新读取。
- 框架升级不能替代应用生命周期检查；在新版本运行 UI 与客户端断连回归。
