## Context

项目同时存在定时采集、自动续签和 UI 手动操作。当前多个模块将“查询失败”折叠为空列表，或在外部通知成功前提前提交状态，导致缓存、告警和 UI 状态与真实执行结果不一致。证书名文件由运维侧保证包含完整证书链，本变更不调整证书文件读取规则。

## Goals / Non-Goals

**Goals:**

- 明确续签失败、部署失败、扫描失败和通知失败各自的状态转换。
- 不在查询结果不可信时覆盖上一次有效缓存。
- 保留腾讯 CDN SSL 下发与旧 `ModifyDomainConfig` 两条部署路径。
- 避免外部命令因输出管道或无超时永久卡住。

**Non-Goals:**

- 不自动重试部署失败。
- 不修改证书名文件及 `fullchain_pem` 的内容约定。
- 不修改私有 Git 中凭据的管理方式。
- 不增加新的云产品支持。

## Decisions

1. 续签状态新增明确的 `deploy_failed` 写入方法。自动流程遇到该状态直接跳过，既不续签也不部署；人工手动部署继续使用已经存在的证书。
2. 腾讯 SSL 扫描结果只覆盖它实际返回的目标。未返回的旧 CDN `modify` 目标保留，确保兼容路径可达；SSL 返回同一目标时以 SSL 结果为准。
3. 产品扫描查询必须传播异常。缓存服务按 provider 原子更新，失败 provider 保留旧数据，并把失败清单返回给调用方。
4. 域名发现按 provider 隔离异常；任一 provider 失败时不覆盖完整映射。采集服务在任一关键阶段失败时抛出聚合异常，不更新成功时间。
5. 告警采用“准备事件 -> 发送 -> 提交 FIRING”的顺序。发送失败不提交状态，下一次扫描继续尝试。
6. acme.sh 使用 `communicate(timeout=...)` 同时消费 stdout/stderr，超时后终止进程并抛出明确异常。日志在命令结束后逐行输出。
7. ECS 到期时间无法确定时使用 `None`，告警层跳过未知值并记录日志。

## Risks / Trade-offs

- [采集部分失败时 UI 会显示失败] -> 错误信息包含具体阶段，成功阶段的数据仍保留在内存，但不标记整轮成功。
- [部署失败状态不自动恢复] -> 符合人工确认要求；手动部署成功后再由成功流程清理状态。
- [外部命令不再实时打印输出] -> 换取可靠的双管道消费和超时控制，命令结束后仍保留完整日志。
- [旧 CDN 目标可能与 SSL 扫描结果重复] -> 以 provider、产品、资源和域名键去重，SSL 结果优先。
