# Design

## Context

见 proposal.md 的问题说明。续签编排还需在执行命令前查询冷却和黑名单，因此不能仅在续签命令内部确定主域名。已有 acme.sh 列表解析与单级通配匹配工具可以直接复用。

## Goals / Non-Goals

**Goals:** 原始目标只解析一次覆盖关系，编排和命令共享解析结果，消除快照与实际证书之间的不一致。

**Non-Goals:** 不更改首次签发规则、DNS 管理域选择和云部署匹配，不迁移或清理历史状态，不执行真实续签。

## Decisions

- 用异步服务解析原始目标，由 acme.sh 客户端读取列表。删除快照推导与最少标签域名兜底，避免未知证书被猜成父证书。
- 为续签与加载接口增加仅限关键字的已解析主域名参数。编排传递已选 Main_Domain，客户端直接构建命令；独立调用不传该参数时自行解析原始目标一次。相较重复查询同名证书，这能固定同一轮重试对象，避免列表变化导致改续其他证书。
- 保留现有 Main_Domain、精确 SAN、单级通配优先顺序，并确保同名 Main_Domain 优先级不依赖 SAN 内容。
- 解析失败在续签编排返回明确失败结果及通知，匹配失败不进入命令重试；已有证书部署保持异常上抛。状态只能在解析成功后使用真实 Main_Domain。
- 本地自签模式直接使用归一化原始目标，保持离线验证能力。
- 保留现有黑名单的两次检查，第二次检查使用实际选中的主域名。

## Risks / Trade-offs

- 旧状态可能按错误父域保存 → 不自动迁移，避免将父证书状态误归属子证书；新操作按实际证书重新记录。
- 查询列表失败会阻止当前操作 → 明确日志和通知，自动采集仍继续处理后续目标。
- 有多个精确 SAN 覆盖时仍按 acme.sh 列表顺序选择 → 维持现有策略；同名 Main_Domain 始终优先。
- 已解析参数仅供服务编排传递 → 在接口文档说明来源，并通过回归测试验证没有二次覆盖匹配。

## Migration Plan

运行隔离单测与 OpenSpec 校验后部署应用，无配置迁移。需要回滚时恢复本次代码版本，不删除证书或状态文件。
